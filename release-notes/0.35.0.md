Connecta 0.35.0 is the planned consolidated release of the #703 rework. This draft will be completed after Phase 5, before publishing.

Node remote MCP writes now require `listen` from `@zackbart/connecta/node`,
which installs the owned transport that prevents hidden HTTP retries. Node
hosts serving `connecta.fetch` without `listen` lose remote writes that worked
in 0.34: those writes are refused before dispatch. Remote MCP reads are unchanged.

Remote MCP writes, like kit writes, connect directly and ignore
`NODE_USE_ENV_PROXY`, `HTTP_PROXY`, `HTTPS_PROXY`, and host proxy dispatchers.
The owned sender has no supported explicit-proxy setting. Operators behind a
mandatory outbound proxy must move writes to a host with approved direct egress
or an approved Workers deployment; keep affected connectors `readOnly` until
then. A connection failure after dispatch remains unknown and non-retryable.
See [Node deployment requirements](../documentation/deploying.md#start-on-node).
