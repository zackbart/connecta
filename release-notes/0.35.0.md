Connecta 0.35.0 brings the provider kit and standard agent surfaces to all 15 maintained providers. Operation search and details expose reviewed API contracts without reading account data; indexed read and write tools complement the retained named tools. Gmail keeps its reviewed exception: draft writes use named tools and sending remains unavailable. Results use consistent list envelopes, narrowing `fields`, signed continuations and truncation paths. The [provider migration guide](../documentation/provider-migration-0.35.md) maps every renamed or removed tool and argument, including retired `raw`/`select` arguments, list keys, paging inputs and wrappers replaced by indexed operations. Update saved programs, pool grants, classification entries and deployment instructions before upgrading, and restart old continuations where the guide requires it.

Pools can opt into a native tool surface for clients with their own tool search, retaining the same classification, scope and invocation enforcement. Native pools include `execute_code` by default; code-off pools provide `read_result` for bounded result paging. The separate `@zackbart/connecta-eve` helper supplies an Eve connection, endpoint instructions and an optional host write gate. Explicit Vercel workload bindings can admit declared agents without separately provisioned Connecta tokens. Existing agent tokens remain supported. See [native tools and Eve agents](../documentation/meta-tools.md#native-tool-surface) and [Vercel workload credentials](../documentation/auth.md#vercel-workload-credentials). The helper requires Node 24 and Eve 0.83.x. Eve 0.83.0 apps need their own undici 8.12.3 override; the repository's development override does not ship with the helper. Its [package guide](https://github.com/zackbart/connecta/blob/main/packages/connecta-eve/README.md#eve-0830-dependency-override) gives the operator steps.

Write outcomes now follow the whole logical call's dispatch evidence (H1). A dispatched write with an uncertain result is non-retryable and requires reading the target before another write; a later refusal or caught program error cannot erase earlier uncertainty. Source or effective write classification prevents automatic replay. Signed continuations also bind the admitted caller and pool owner when downstream identity varies by caller, refusing cross-caller continuation before dispatch. Security fixes strengthen credential withholding, response safety, authentication bounds, OAuth state and cancellation while keeping activity records free of request and response payloads.

On Node, remote MCP writes now use the owned transport and are sent once even when the HTTP stack or a host dispatcher would retry. Serve with `listen` from `@zackbart/connecta/node` and install the template's exact optional peer, `undici@6.29.1`. Node hosts serving `connecta.fetch` without `listen` lose remote writes that worked in 0.34: these are refused before dispatch. Remote MCP writes, like kit writes, connect directly and ignore `NODE_USE_ENV_PROXY`, `HTTP_PROXY`, `HTTPS_PROXY` and host proxy dispatchers; no explicit proxy setting is supported. A deployment requiring an outbound proxy must keep affected connectors read-only until approved direct egress or a Workers deployment is available. Remote MCP reads retain their existing transport. See [Node deployment requirements](../documentation/deploying.md#start-on-node).

The maintained Infisical, Notion and Mixpanel API providers and their package subpaths are removed. Replace Notion and Mixpanel with generic `remoteMcp()` connections to their hosted servers, then rediscover live tool names, schemas and permissions. Infisical has no packaged replacement; remove it or supply a deployment-owned connector. Hosted connections do not inherit removed providers' API coverage or value-safety projections. Vercel environment-variable `value` arguments are now `writeOnly`; hosts must treat them as private write inputs, and reads and write replies withhold their values. The [migration guide](../documentation/provider-migration-0.35.md) also covers response-media and numeric-path validation, changed error meanings and each provider's exact upgrade actions.

Deployments using unchanged tools can ignore unrelated provider mappings; deployments without the removed providers need no replacement connections. Existing pools keep the meta-tool surface unless configured otherwise, and deployments without Eve or Vercel-hosted agents need neither new integration. No database conversion or agent-token rotation is required solely for 0.35.0. Workers deployments do not need Node's transport peer or startup changes. The current core remains in place: the deferred Effect HttpRouter, effect/sql and Effect McpServer rewrites are future work. Follow [Upgrade an existing deployment](../documentation/deploying.md#upgrade-an-existing-deployment) for the installed-package handoff.
