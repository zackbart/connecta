`clerkAuth({ organizationId })` lets one Clerk instance serve many deployments, one Organization each. Only that Organization's members are admitted, on MCP OAuth tokens (JWT and opaque) and operator sessions. Membership confirmed with Clerk's Backend API is the only organization rule: organization claims in tokens and sessions are never read. Each answer is cached per Organization and user for 60 seconds from the start of its lookup (30 for a non-member), and requests that miss the cache together share one lookup, so an older answer never replaces a newer one and a removed member is refused from 60 seconds after removal even while their access token is still valid. A failed, oversized, or timed-out lookup refuses admission. A caller that leaves stops waiting without cancelling the lookup for others, and every lookup ends its Backend API request and body once it is answered or abandoned. In organization mode a JWT's issuer and subject, and a session's, must be this instance's and match the looked-up user. Organization roles grant nothing; maintainers and pool members stay in code. Organization mode requires resource-bound tokens, so a nonempty `allowedOAuthClientIds` throws at construction, as does a malformed `organizationId`. The Node template reads `CLERK_ORGANIZATION_ID`.
