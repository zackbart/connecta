`clerkAuth({ organizationId })` lets one Clerk instance serve many deployments, one Organization each. Only that Organization's members are admitted, on MCP OAuth tokens (JWT and opaque) and operator sessions. Membership confirmed with Clerk's Backend API is the only organization rule: organization claims in tokens and sessions are never read. Each answer is cached for at most 60 seconds per Organization and user (30 for a non-member), so a removed member is refused within a minute even while their access token is still valid. A failed, oversized, or timed-out lookup refuses admission, and every lookup ends its Backend API request when admission returns. In organization mode a JWT's issuer and subject, and a session's, must be this instance's and match the looked-up user. Organization roles grant nothing; maintainers and pool members stay in code. Organization mode requires resource-bound tokens, so a nonempty `allowedOAuthClientIds` throws at construction, as does a malformed `organizationId`. The Node template reads `CLERK_ORGANIZATION_ID`.
