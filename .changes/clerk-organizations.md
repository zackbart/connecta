`clerkAuth({ organizationId })` lets one Clerk instance serve many deployments, one Organization each. Only that Organization's members are admitted, on MCP OAuth tokens (JWT and opaque) and operator sessions. Membership confirmed with Clerk's Backend API is the only organization rule: organization claims in tokens and sessions are never read. Each answer is cached per Organization and user for 60 seconds from the start of its lookup (30 for a non-member). An answer is cached only if no lookup that started later has already cached one, so an older answer never replaces a newer one, and a removed member is refused from 60 seconds after removal even while their access token is still valid. The cache trusts an answer only while the clock reads between its lookup's start and the end of its TTL, so a step forward ends it early, a step back before the start ends it, and an answer found expired is never revived. Each request runs and owns its own lookup, as Workers require, and a caller that leaves cancels only that lookup. A failed, redirected, oversized, or timed-out lookup refuses admission and is not cached, and every lookup ends its Backend API request and body on every outcome. In organization mode a JWT's issuer and subject, and a session's, must be this instance's and match the looked-up user. Organization roles grant nothing; maintainers and pool members stay in code. Organization mode requires resource-bound tokens, so a nonempty `allowedOAuthClientIds` throws at construction, as does a malformed `organizationId`. The Node template reads `CLERK_ORGANIZATION_ID`.
