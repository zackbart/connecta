`clerkAuth({ organizationId })` lets one Clerk instance serve many deployments, one Organization each. Only that Organization's members are admitted, on MCP OAuth tokens (JWT and opaque) and operator sessions. Membership confirmed with Clerk's Backend API is the only organization rule: organization claims in tokens and sessions are never read. Each answer is cached per Organization and user for 60 seconds from the start of its lookup (30 for a non-member). An answer is cached only if no lookup that started later has already cached one, so an older answer never replaces a newer one, and, assuming no unseen clock rollback within the TTL window, a removed member is refused from 60 seconds after removal even while their access token is still valid. An unseen rollback within that window can extend admission beyond 60 seconds of elapsed time. The cache trusts an answer only while the clock reads between its lookup's start and the end of its TTL, so a step forward ends it early, a step back before the start ends it, and an answer found expired is never revived. Each request runs and owns its own lookup, as Workers require, and a caller that leaves cancels only that lookup. A failed, redirected, oversized, or timed-out lookup refuses admission and is not cached, and every lookup ends its Backend API request and body on every outcome. In organization mode a JWT's issuer and subject, and a session's, must be this instance's and match the looked-up user. Organization roles grant nothing; maintainers and pool members stay in code. Organization mode requires resource-bound tokens, so a nonempty `allowedOAuthClientIds` throws at construction, as does a malformed `organizationId`. The Node template reads `CLERK_ORGANIZATION_ID`.

Organization-mode Backend API reads (membership and extra opaque verification) are capped at 16 concurrent calls per isolate and two per identity, without sharing request-owned I/O or queuing. Excess calls and Clerk 429 backoff return retryable `503 organization_lookup_busy` with `Retry-After` and are never cached; valid membership cache hits still work. Backoff honors a bounded Retry-After (1–60 seconds, default ten). Operators must rate limit ingress against Clerk's shared per-instance quota. When the eviction floor suppresses a newer answer, it invalidates any older cached answer for that identity.
