`notion()` over an integration token now withholds the query of pre-signed file links embedded in text, such as a page's Markdown (`GET`/`PATCH /v1/pages/{page_id}/markdown`) and a completed async task's result, as it already withheld the signature of file URL fields; the scan sees through Markdown and HTML escaping. A 5xx on a write that carries Notion's `retry_guidance` relays it and is not retryable. `integration_create_page` and `integration_append_blocks` split text longer than Notion's 2,000-character rich-text run limit into consecutive runs instead of sending a request Notion rejects, and refuse text no single value can carry. Failures follow Notion's current contract: a 429 whose reason is `public_api_request_blocked` is no longer retryable, the retry window falls back to the body's `additional_data.retry_after`, a 403 names the workspace block limit, and a 5xx on a write that Notion reports as committed names the created object or appended blocks so the caller reads them instead of repeating the write. A data source query stopped at Notion's 10,000-result cap reports `incomplete: true` from `integration_query_data_source` and `page.hasMore` without `page.next` from the generic read. Projections name native Notion icons and custom emoji and read an `unsupported` formula or rollup value as `null`. The OAuth connector classifies `notion-ai-search`, `notion-get-self`, `notion-get-tool-access`, and `notion-download-skill` as reads. The guide routes whole-page reads and Markdown writes through the page Markdown endpoints.
