Gmail is now full read-write by default; the draft-only mode is gone (#1398). The connection requests `https://mail.google.com/`, `https://www.googleapis.com/auth/gmail.settings.basic` and `https://www.googleapis.com/auth/gmail.settings.sharing` instead of `gmail.readonly` and `gmail.compose`. New named tools send, reply and forward mail (`send_message`, `forward_message`, `send_draft`), delete drafts, relabel, archive, mark read, star, trash, restore and permanently delete messages and threads (singly and in batches of up to 1,000), manage labels and filters, and read and change the vacation responder. `gmail_api_write` is added and every one of the 79 indexed Gmail methods now has a read, write or destructive verdict, so forwarding, delegates, send-as, S/MIME, IMAP/POP, language, client-side encryption, import/insert and watch/stop are reachable; settings reads withhold SMTP passwords, S/MIME private keys and CSE wrapped keys. Sends and permanent deletes are destructive. Existing deployments must re-grant before upgrading: in OAuth mode every connected person, and the maintainer for a shared connection, reconnects and consents to the new scopes; in delegation mode a Workspace super administrator replaces the Gmail scopes on the service account's domain-wide delegation entry (Admin console → Security → Access and data control → API controls → Domain-wide delegation) with exactly those three. Until then, in delegation mode every Gmail call fails `provider_permission_denied`, because the token request names scopes the entry does not grant; in OAuth mode an old grant still reads mail, but sends, mailbox changes and settings fail `provider_permission_denied` until the person reconnects. To keep an agent from sending or deleting, set `readOnly: true` or list only the tools it may use in its pool.
