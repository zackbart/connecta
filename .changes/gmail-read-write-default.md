Gmail is now full read-write by default; the draft-only mode is gone (#1398). The connection requests `https://mail.google.com/`, `https://www.googleapis.com/auth/gmail.settings.basic` and `https://www.googleapis.com/auth/gmail.settings.sharing` instead of `gmail.readonly` and `gmail.compose`. New named tools send, reply and forward mail (`send_message`, `forward_message`, `send_draft`), delete drafts, relabel, archive, mark read, star, trash, restore and permanently delete messages and threads (singly and in batches of up to 1,000), manage labels and filters, and read and change the vacation responder. `gmail_api_write` is added and every one of the 79 indexed Gmail methods now has a read, write or destructive verdict, so forwarding, delegates, send-as, S/MIME, IMAP/POP, language, client-side encryption, import/insert and watch/stop are reachable; settings reads withhold SMTP passwords, S/MIME private keys and CSE wrapped keys. Sends and permanent deletes are destructive. In delegation mode the token request names the new scopes, so every Gmail call fails `provider_permission_denied` until a Workspace super administrator adds those three to the service account's domain-wide delegation entry (Admin console → Security → Access and data control → API controls → Domain-wide delegation); add them before upgrading, keeping `gmail.readonly` and `gmail.compose` until the upgrade is serving. In OAuth mode an existing `gmail.readonly` and `gmail.compose` grant keeps working: reads continue, and because `gmail.compose` already authorizes `messages.send`, `drafts.send` and `drafts.delete`, sending, replying, forwarding, sending and deleting drafts work immediately. Relabeling, archiving, trash and restore, permanent deletes, label and filter changes, the vacation responder and other settings, and message import and insert fail `provider_permission_denied` until the person, or the maintainer for a shared connection, reconnects and consents to the new scopes. Creating filters, starting a mailbox watch, importing messages and adding CSE identities, key pairs or S/MIME certificates are destructive. Hatch sends admit only MIME that reads exactly as a mail client reads it (US-ASCII, UTF-8, ISO-8859 and windows-125x charsets; no header comments, extended `filename*=` parameters or ambiguous boundaries) and inspect every decoded part for withheld links, and forwards remove the original's `Bcc` and `Resent-Bcc` headers. To keep an agent from sending or deleting, set `readOnly: true` or list only the tools it may use in its pool.
