A `readOnly: true` pool can now grant exact writes in a new `writes` field (`writes: ["tickets.save_issue"]`), so one agent endpoint serves whole connectors read-only plus a few named writes (#1409). Granted writes run through `call_destructive_tool`, programs and native write tools, and show in `search_tools`, `connecta.search`, `connecta.describe` and the native tool list; every other write, including one a vendor adds later, stays hidden and is refused with `read_only_endpoint`. Such a pool presents as writable: it lists `call_destructive_tool`, annotates `execute_code` as a write and reports `readOnly: false` in endpoint facts. The meaning of `tools` is unchanged: an exact write address there still grants no write on a read-only pool. Construction throws a `ConfigError` for `writes` on a writable pool, an empty list, a bare connector id, an unknown connector, and an address an `api()` catalog lacks. A new pool `unlisted` field names connectors in the pool that endpoint facts mark `unlisted: true`; `@zackbart/connecta-eve` leaves them off the model's roster and guide while they stay callable at the same endpoint. `connectaInstructions` takes `rosterMaxBytes` to change the 512-byte roster cap. `describeConfig()` and the operator contract carry each pool's `writes` and `unlisted`, and the operator endpoints view shows granted writes and marks unlisted connectors.
