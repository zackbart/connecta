Every `fields` argument now states where its paths start, with one valid example, in its schema description: `the result` for named reads, `each item in items` for named lists and searches, and `the response body in data` for `*_api_read` and `*_api_write`. Anchors are unchanged. Below the first segment, named tools refuse an undeclared property only inside an object their schema closes with `additionalProperties: false`, with `invalid_args` naming the entry position, the segment and the declared properties; first-segment checks are unchanged. A declared path the response lacks is never refused. Hatch reads and writes still check only the first segment before dispatch, and now return `warnings` naming each `fields` entry that matched nothing in a nonempty response, with the properties the operation declares where matching stopped and never the response's own keys. Warnings are bounded to 10 of at most 512 characters and 4,096 characters together, reviewed vendor warnings included, followed by an omitted count.
