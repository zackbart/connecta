Program writes no longer hide how they failed or leave altered. `write_outcome_unknown` now leads with the tool's words when a tool answered `isError`, and carries `unknownWrites` with each write's address, code and redacted message, plus `toolAnswered: true`; the outcome stays unknown and nothing is sent again. A tool's `isError` text now reaches every agent surface up to 4,096 UTF-8 bytes instead of 512, cut only between tokens and marked, so an approval link or request id arrives usable. A program's report is redacted against the run's final credentials before any cut and bounded per message, in total, and by `execute.maxResultChars`. A program write whose arguments hold a credential the request already sent is refused before dispatch with `invalid_args`, rather than sent with `[redacted]` in place of the match, which could first appear on a program's second call. Program arguments no longer match a credential's public prefix or an identifier sent beside it, so reads and writes naming them leave as written. Operator logs name a tool's own failure `DownstreamToolError` rather than `Error`.
