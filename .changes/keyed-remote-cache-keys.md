Remote MCP catalog-cache and negotiation-verdict partitions are now deployment-keyed. Their secret-bearing inputs (static auth header values, a static OAuth client secret, the userinfo, query and fragment of the endpoint and client metadata URLs, operator-managed and request-resolved credentials, custom connector credential values and OAuth token responses) enter stored keys through HMAC-SHA-256 under a key that is never stored. `encryptedCredentialVault()` derives that key from its credential key and exposes it through a new optional host-only vault method, `storageDigestKey()`. Without a vault, or with a custom vault that lacks the method, each process or isolate uses its own random key, so those connectors' cached catalogs and verdicts are reused within that process or isolate only. Partitioning by owner, credential, token and epoch is unchanged. After the upgrade, each affected partition refills its cache once with one handshake and catalog listing. Earlier entries are not read and expire on their own TTLs.
