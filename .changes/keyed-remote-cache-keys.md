Remote MCP catalog-cache and negotiation-verdict storage keys no longer include plain hashes of secret material. Static auth header values, a static OAuth client secret, the URL's userinfo, query and fragment, operator-managed and request-resolved credentials, custom connector credential values and OAuth token responses now enter those keys only through HMAC-SHA-256 under a key that is never stored. `encryptedCredentialVault()` derives that key from its credential key and exposes it through a new optional host-only vault method, `storageDigestKey()`. Without a vault, or with a custom vault that lacks the method, a random per-process key is used. Partitions stay exact, but each process or isolate then keeps its own cached catalogs and verdicts for connectors with secret-bearing configuration. Partitioning by owner, credential, token and epoch is unchanged. After the upgrade, each affected partition performs one extra handshake and catalog listing. Entries stored by earlier releases are no longer read and expire on their own TTLs: verdicts within six hours, catalogs within the configured maximum catalog TTL, and refresh baselines within 48 hours.
