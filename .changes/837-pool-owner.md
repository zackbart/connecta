Pools take an optional `owner`, the Google Workspace address agents in that pool act as on a Workspace connector (`gmail()`, `drive()`, `sheets()`, `slides()`, `forms()`, `docs()`) whose `subject` is a mapping function, so one connector serves a pool per person instead of one connector per mailbox. People always act as themselves through the mapping, in any pool. An agent acts as the owner of the pool it came through, resolved before and instead of the mapping, which is never called for an agent. An agent in a pool without an owner fails `auth_required` before any request leaves, and the message names no address. A fixed `subject` address still applies to every caller, agents included, and ignores owners. Nothing in arguments, headers, or programs can choose the owner. `owner` must be a Workspace email address, checked at construction by the rule a fixed `subject` uses, and `describeConfig()` pools add `owner` (`null` when unset). Breaking for agents only: people and fixed subjects behave as before. In 0.32 a `cta_` token reached the mapping function, which usually answered `undefined` for a caller with no principal (`auth_required`). Now an agent never reaches it, so a mapping that answered for machine tokens, by token subject or otherwise, no longer applies; set that address as the `owner` of the agent's pool.
