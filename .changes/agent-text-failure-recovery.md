Failure messages now give the exact next step in one read. An auth error that carries a handoff says so in `nextAction` (`{ url, purpose }`, or `{ action: "contact_operator", purpose }` when there is no link) instead of sending the agent to `authorize_connector` for the same thing, and its `instructions` address the person opening the link; `authorizationUrl`, `operatorUrl`, `credential` and `instructions` keep their meaning, and anything branching on `nextAction.tool === "authorize_connector"` must also accept the new shapes. A program that finishes with nothing to read gets a `note`, which after a write says not to rerun it; an unawaited read in a program that finished gets the await hint there too. A truncated direct read offers a `connecta.result` loop over the retained result in one program when that fits the host-call budget, and repeats the read otherwise. Budget, write-outcome, read-only, unknown-tool, empty-search, program-error and direct-call-shape messages name what to do next; `invalid_args` with complete findings no longer sends the agent to search first, and its example uses a named placeholder rather than an empty string. The `usage` paging example no longer sets `maxBytes`, which could exhaust the host-call budget.
