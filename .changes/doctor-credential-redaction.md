`connecta doctor` no longer prints `CONNECTA_TOKEN`, `CF_ACCESS_CLIENT_ID` or `CF_ACCESS_CLIENT_SECRET` when the server it checks echoes request headers back, as a misdirected `--url`, a proxy or an error page quoting the request could. Doctor prints only its own text, HTTP status codes, counts and identifiers that pass its check. A failed `/health` or MCP request reports `HTTP <status> from /health` or `MCP <status> from <endpoint>` without the body, a JSON-RPC error reports its code only, and an execution check reports whether the tool errored or returned a wrong result, without the result. The health status, executor name, connector ids, tool names and protocol version print only as plain identifiers that share no 8-character run with a credential (case-insensitive), otherwise as `<unprintable>`; an executor name with spaces or other characters is no longer printed. Doctor withholds the MCP client library's console messages and fails when the library excludes or flags a tool. The `--config` snapshot replaces any key or value containing a credential with `[redacted]` before it is serialized. Doctor refuses a credential shorter than 16 characters by variable name, refuses responses over 64 KiB from `/health` or 4 MiB from the config endpoint or an MCP reply, reads at most 4 tools/list pages, times out `initialize` after 10 seconds, stops the whole run after 60 seconds, and fails an unreadable `--dotenv` file with its error code, without the path. A server that deliberately re-encodes a credential it was sent is out of scope, because it already holds the credential.
