Search returns fully determined API reads as `readyCalls` on the first page: `{ address: "<id>.<x>_api_read", args: { path }, classification: "read", summary }`, ready to pass unchanged to `connecta.call` or `call_tool`. Only a reviewed GET served by the hatch's read tool with no path template, required parameter or required body qualifies, and every object word of the query must belong to a whole resource name, a path segment or the operationId, stated in order (summaries and parts of compound segments never count); an exact name, or a complete authored tool whose name adds nothing to the query, suppresses ready calls; anything needing an id, method choice or argument still routes through `_api_search` and `_api_details`. Ready calls pass the same endpoint, connector, safety, hidden-tool and grant checks as other discovery, are computed offline, and offer only the top-ranked operation per connector, at most three per page. Listing Granola notes, Vercel deployments or Stripe customers now takes two host calls instead of four.
