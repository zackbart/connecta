Agents move from `/mcp/<pool>` to `/agent/<pool>`. An agent endpoint admits only the built-in `cta_` adapter and a member agent of that pool, serves exactly the pool's tools with its `readOnly`, binds result handles to `/agent/<pool>`, answers a missing or invalid credential with a machine-only `WWW-Authenticate: Bearer` challenge, and publishes no protected-resource metadata. It never runs Clerk or Access and ignores cookies, Clerk handshake parameters, `ctx.access`, and Access headers. Only a raw pathname byte-equal to `/agent/` plus a pool name is an agent endpoint; every other path in the agent namespace (any case, escapes, doubled slashes, trailing slash, extra segments) is routed first and answers the pool 404 before auth, so no path Cloudflare Access bypasses as `/agent/*` reaches a human route. Breaking: `/mcp`, `/mcp/<pool>`, and the operator, connect, and callback routes refuse `cta_` tokens without reading token storage (401 on MCP and operator data routes, 403 on interactive-only routes), so point every agent at `/agent/<pool>`; `connecta doctor` checks `/agent/<pool>` for a `cta_` token and requires `--pool`, and the Node template's doctor checks `/agent/local-machine`. Deployments behind Cloudflare Access add one self-hosted Access application per agent hostname for `<host>/agent/*` with a single Bypass policy beside the Worker-level application, after which agents send only their `cta_` token (deploying guide, "Agent endpoints behind Cloudflare Access"). The `agent_not_maintainer` denial reason is removed.
