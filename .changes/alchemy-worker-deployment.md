The Worker example now deploys with Alchemy. `examples/worker/alchemy.run.ts` declares the Worker, its vars and in-stack secrets, the D1 database (retained on `alchemy destroy`), the Worker Loader, the Worker-level Cloudflare Access application with Managed OAuth, and the `/agent/*` bypass application; deploy with `npx alchemy deploy --stage production`. `wrangler.jsonc` remains for `wrangler dev` only. Install `alchemy@2.0.0-beta.83`, `effect@4.0.5`, and `@effect/platform-node@4.0.5` exactly; the Alchemy CLI needs Node 24.11.1 or later. Never commit `.alchemy/` or `.env`: local state records secret values in plaintext. The example ships its ignore rules as `examples/worker/gitignore`, because npm strips `.gitignore` from packages; a copied deployment renames it to `.gitignore` before the first `git add`, which keeps `.alchemy/`, `.env*`, `.dev.vars*`, `.wrangler/`, and `node_modules/` out of git. Custom domains are not yet verified with Alchemy; verify a custom hostname before agents use it. A Worker already deployed with Wrangler moves once by adopting its resources, as the example README describes.
