Settle API write failures from the whole call's request ledger. A single vendor refusal remains a known failure regardless of its error code; later refusals and handler errors cannot advertise retrying earlier resource dispatches. Preserve GitHub and Cloudflare preflight retry advice and Google Docs composite-create authorization, outcome, and read retry verdicts through recovery wrappers. A write is a known failure only on positive evidence: once a call's outcome is decided, a request still waiting to leave is never sent; no network failure proves a write unsent, a refused connection included, because one fetch can hide several attempts (Node resends after HTTP 421 and an HTTP/2 refused stream, and a dispatcher such as undici's `RetryAgent` can retry further), so a write whose send fails is a non-retryable unknown outcome while a read stays retryable; and a custom `api()` handler's write that fails after the handler started is an unknown outcome, because requests it sends outside `ctx.fetch` are invisible. A direct write outside an invocation that times out after it may have left is likewise a non-retryable unknown outcome that keeps its timeout code, and a blank REST `idempotencyKey`, which fetch would send empty, is refused with `invalid_args` before dispatch instead of counting as proof that a retry is safe. Notion's 409 on a write is now a non-retryable `conflict` to reconcile instead of retryable advice; reads keep backing off.
