Settle API write failures from the whole call's request ledger. A single vendor refusal remains a known failure regardless of its error code; later refusals and handler errors cannot advertise retrying earlier resource dispatches. Preserve GitHub and Cloudflare preflight retry advice and Google Docs composite-create authorization, outcome, and read retry verdicts through recovery wrappers. A write is a known failure only on positive evidence: once a call's outcome is decided, a request still waiting to leave is never sent; a connect-phase network error proves a write unsent only when the runtime itself reported it, the request was not cancelled, and no streamed, `Blob`, or form-data body was involved (on Workers, where no such error is named, a refused or reset write is an unknown outcome); and a custom `api()` handler's write that fails after the handler started is an unknown outcome, because requests it sends outside `ctx.fetch` are invisible. Notion's 409 on a write is now a non-retryable `conflict` to reconcile instead of retryable advice; reads keep backing off.
