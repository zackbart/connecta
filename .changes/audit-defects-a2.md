Close audit defects in the HTTP providers, `api()`, and `remoteMcp()`. A dispatched write is never advertised as retryable once the downstream may have acted: a 5xx (a gateway's 502 to 504 included), a broken-off reply, or a connection lost after sending is now a non-retryable unknown outcome in `remoteMcp()`, in `api()` handlers that fail with a network error, and in Tithe.ly, Planning Center, Church Community Builder, Breeze (whose writes use GET), Overflow, Infisical, and GitHub's REST tools; reads keep `unavailable`. A write answered with HTTP 401 is never resent: `remoteMcp()` OAuth, `api()` downstream OAuth, the Google Workspace providers, and Infisical renew or discard the rejected credential for a deliberate repeat and report an unknown outcome, and a failure during that renewal is never retryable (an authorization verdict keeps its code). Reads are still refreshed and sent once more. Google Workspace and Infisical honor the served classification before the HTTP method when deciding 401 replay. Every maintained API provider now uses one shared failure decision based on that served classification and transport dispatch facts, including GET tools overridden to write. Dispatched served writes keep non-retryable advice and `writeOutcome: "unknown"` even with an idempotency key or an idempotent-operation hint. Google product recovery advice preserves the shared retry verdict and unknown marker. A catalog-wide regression sweep covers every API provider and tool with write/read overrides and HTTP 503 or a reset after send on Node and Workers. A Google write answered 401 retains its authorization code and handoff with `writeOutcome: "unknown"`. A `remoteMcp()` write is held to one send per call, whatever JSON-RPC message carries it: a redirect answering a write, even under `redirects: "same-origin"`, fails it as an unknown outcome instead of sending it to the new location, and a write given no definition is no longer relisted and sent again after a `HeaderMismatch` answer. A remote tool call that loses its dispatch record is refused before sending unless active calls prove it is read-only; a missing record never grants a fresh write attempt. An error whose write outcome is unknown now carries `writeOutcome: "unknown"`, so an authorization failure after a write left still counts that write in `writes.unknown`, and a program that catches it fails with the verdict and its handoff instead of returning its own value. A direct `api()` call outside an invocation classifies its tool by the registry's rule, so contradictory hints count as a write. Church Community Builder and Tithe.ly drop their sensitive fields from every result, `raw: true` and the hatches included, unless deployment code sets the new `sensitiveFields: "return"` option; Breeze hatches no longer return a calendar's keyless feed address; Planning Center never returns a webhook signing secret or an organization secret. Maintained providers derive connector contexts so the caller, admission permit, recovery facts, and sent-secret redaction survive the copy, and `api()` no longer mutates the registry's context.
