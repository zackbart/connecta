Close audit defects in the HTTP providers, `api()`, and `remoteMcp()`. A dispatched write is never advertised as retryable once the downstream may have acted: a 5xx (a gateway's 502 to 504 included), a broken-off reply, or a connection lost after sending is now a non-retryable unknown outcome in `remoteMcp()`, in `api()` handlers that fail with a network error, and in Tithe.ly, Planning Center, Church Community Builder, Breeze (whose writes use GET), Overflow, Infisical, and GitHub's REST tools; reads keep `unavailable`. A write answered with HTTP 401 is never resent: `remoteMcp()` OAuth, `api()` downstream OAuth, the Google Workspace providers, and Infisical renew the credential for a deliberate repeat and report an unknown outcome, and a failure during that renewal is never retryable (an authorization verdict keeps its code). Reads are still refreshed and sent once more. A `remoteMcp()` write is held to one send per call, whatever JSON-RPC message carries it: a redirect answering a write, even under `redirects: "same-origin"`, fails it as an unknown outcome instead of sending it to the new location, and a write given no definition is no longer relisted and sent again after a `HeaderMismatch` answer. An error whose write outcome is unknown now carries `writeOutcome: "unknown"`, so an authorization failure after a write left still counts that write in `writes.unknown`, and a program that catches it fails with the verdict and its handoff instead of returning its own value. A direct `api()` call outside an invocation classifies its tool by the registry's rule, so contradictory hints count as a write. Church Community Builder and Tithe.ly drop their sensitive fields from every result, `raw: true` and the hatches included, unless deployment code sets the new `sensitiveFields: "return"` option; Breeze hatches no longer return a calendar's keyless feed address; Planning Center never returns a webhook signing secret or an organization secret. Maintained providers derive connector contexts so the caller, admission permit, recovery facts, and sent-secret redaction survive the copy, and `api()` no longer mutates the registry's context.
