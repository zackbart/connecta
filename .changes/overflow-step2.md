Standardize Overflow's agent surface for 0.35.0. `overflow_api_get` becomes `overflow_api_read`, `overflow_api_mutate` becomes destructive `overflow_api_write`, and new `overflow_api_search`/`overflow_api_details` discover the 38 reviewed operations. `list_tap_events`, `list_webhooks` and `list_webhook_event_logs` move to indexed reads of `/tap/events`, `/webhooks` and `/webhooks/{webhookId}/event-logs`; flattened rows become vendor records under hatch `data.data`. Hatch query pairs become an object, with repeated arrays under bracketed names; `{ result }` becomes `{ status, data, page? }`. Paths remain relative to `/api/v3`, unindexed calls retire, and subscription creation uses `/subscriptions/{donorId}` rather than undocumented `/subscriptions` plus a body `donorId`. Remove `raw` from all named reads. Named `page` becomes opaque `cursor`, list noun keys become `items`, numbered `page`/`limit`/`totalCount` metadata becomes `hasMore`/optional `nextCursor`/vendor-stated `total`, payment methods gain paging, and delivery tokens move into hatch `page.nextCursor` with the vendor parameter named explicitly. All named reads and both call hatches gain narrowing `fields`. Preserve text `/health`, JSON-string or plain-text refund acknowledgements and empty write acknowledgements; refuse other unexpected non-JSON successes. Permanently strip webhook keys matching `secret|signing|hmac` case-insensitively, including nested delivery payloads. HTTP 422 becomes `invalid_args`; 409 stays generic. The sensitive set remains empty, writes still need host approval and have no idempotency key, and the maintained provider setup and 0.35 migration describe the exact replacements.
