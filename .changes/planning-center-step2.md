Standardize Planning Center's agent surface for 0.35.0 (#703). `pco_api_get` becomes `pco_api_read`, `pco_api_mutate` becomes the destructive `pco_api_write`, and new `pco_api_search`/`pco_api_details` discover the ten pinned products' operations. Hatch query pairs become an object, `{ result }` becomes `{ status, data, page? }`, arbitrary unindexed paths and per-call `version` are removed, and `fields` narrows declared results. Every named `raw` is removed; named-list `perPage`/`offset` become `limit`/opaque `cursor`, noun keys become `items`, `page.nextOffset` becomes `nextCursor`, terminal cursors are omitted, and named `totalCount` is removed for now (the hatch retains `meta.total_count`). `get_plan.plan` moves to the top level; `itemsTruncated`/`teamMembersTruncated` become `truncated` paths. Acknowledged workflow-card actions return `{ ok: true }`. People's documented duplicate 409 now means `conflict`. Private calendar codes, private file destinations and opaque webhook payload/body/header values stay withheld alongside permanent credentials, without a widening argument or option.

Removed wrappers move to the indexed method/path: `add_person_email` → POST `/people/v2/people/{personId}/emails`; `add_person_phone_number` → POST `/people/v2/people/{personId}/phone_numbers`; `list_lists` → GET `/people/v2/lists`; `list_list_people` → GET `/people/v2/lists/{listId}/people`; `run_list` → POST `/people/v2/lists/{listId}/run`; `add_workflow_card_note` → POST `/people/v2/people/{personId}/workflow_cards/{cardId}/notes`; `list_forms` → GET `/people/v2/forms`; `list_form_submissions` → GET `/people/v2/forms/{formId}/form_submissions`; `add_plan_item` → POST `/services/v2/service_types/{serviceTypeId}/plans/{planId}/items`; `list_songs` → GET `/services/v2/songs`; `list_song_arrangements` → GET `/services/v2/songs/{songId}/arrangements`; `list_group_events` → GET `/groups/v2/events` or `/groups/v2/groups/{groupId}/events`; `list_check_in_events` → GET `/check-ins/v2/events`; `list_check_in_event_periods` → GET `/check-ins/v2/events/{eventId}/event_periods`; `list_check_ins` → GET `/check-ins/v2/check_ins` or `/check-ins/v2/events/{eventId}/check_ins`; `list_calendar_event_instances` → GET `/calendar/v2/event_instances`; `list_signups` → GET `/registrations/v2/signups`; `list_signup_attendees` → GET `/registrations/v2/signups/{signupId}/attendees`; `list_batches` → GET `/giving/v2/batches`; `list_pledge_campaigns` → GET `/giving/v2/pledge_campaigns`; `list_pledges` → GET `/giving/v2/pledge_campaigns/{pledgeCampaignId}/pledges`; `list_recurring_donations` → GET `/giving/v2/recurring_donations`; `list_webhook_subscriptions` → GET `/webhooks/v2/webhook_subscriptions`. Their old id arguments fill path slots; paged-read `perPage` becomes query `per_page` and continuation uses signed query `offset`, while attribute/filter/include argument mappings are listed completely in the Planning Center section of `documentation/provider-migration-0.35.md`. Additive writes moved to the hatch now require approval for a destructive tool. Operator setup moves to `documentation/providers.md` and agent conventions are generated.
